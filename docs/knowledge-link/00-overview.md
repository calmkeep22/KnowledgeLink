# 개발 지식 연결 서비스 MVP 개발 명세

버전 0.2 · 2026-09-12 · 1인 개발 MVP (해커톤 → 포트폴리오) · 서비스명 가칭

혼자 개발하는 기준으로 핵심 명세 6개만 유지합니다. Jira 이슈와 GitHub PR을 수집해 서로 연결하고, 새 업무와 비슷한 과거 업무·관련 PR·해당 경험이 있는 개발자를 근거와 함께 보여 줍니다. 사용자는 접근 권한이 있는 Jira 프로젝트·GitHub 저장소의 자료만 결과로 받습니다.

> "이 문제, 우리 회사에서 이미 누가 풀지 않았을까?"

## 문서 목록

현재 구현의 기준은 이 디렉터리의 명세다. 기술 스택은 Spring Boot + React·TypeScript + PostgreSQL·pgvector·pg_trgm이다.

2026-09-12 반영 결정: 생성물의 근거 접근이 바뀌면 전체 비공개, SYNC/INDEX/AI 공통 실행 슬롯, Jira 연결+불변 ID 식별, WORK_ITEM/CODE_CHANGE 공통 결과 계약. 세부 규칙은 아래 문서를 따른다.

## MVP 핵심

[기능명세서와 유즈케이스](01-functional-spec.md)

관리자가 등록한 Jira 프로젝트와 GitHub 저장소를 실제 API로 동기화하고 색인합니다. 개발자가 Jira 이슈 키나 업무 설명을 입력하면 서버가 권한 범위 안에서 유사한 과거 업무를 찾고, 연결된 PR과 관련 경험이 있는 개발자를 근거와 함께 반환합니다. AI가 추정한 이슈·PR 연결은 명시 연결과 구분해 표시합니다. 근거가 부족한 질문은 확인 불가로 답합니다.

[화면 흐름과 간단한 와이어프레임](02-screen-flow.md)

초기에는 단일 조직·Jira 프로젝트 2개·GitHub 저장소 2개 이하·AI 작업 동시 1개·유료 AI 비활성으로 시작합니다. 평가 질의 30개로 검색 품질·비용·지연을 측정한 후 운영값을 정합니다.

[ERD와 상태 전이](03-erd-state.md)

## 보조 계약

[API 명세서](04-api-spec.md)

OpenAPI와 AI JSON Schema는 구현을 시작할 때 로컬 프로젝트의 기계 계약으로 작성하며 이 문서에는 싣지 않습니다. 문서 검증 통과는 실제 연동·검색 품질 테스트 통과를 의미하지 않습니다.

## 구현 전 결정

[테스트 체크리스트](06-test-checklist.md)

데모 데이터는 본인이 만든 Jira Cloud 사이트와 GitHub 저장소에 시나리오 데이터를 생성해 사용합니다. 배포는 앱 서버 1대와 Amazon RDS for PostgreSQL로 하고 비용은 최소로 유지합니다. 개발은 로컬과 fake AI로 비용 없이 진행하고 서버는 데모·심사 기간에만 운영합니다. 외부 AI로 보내는 필드 범위와 AI 공급자(OpenAI API 또는 Amazon Bedrock)는 유료 평가 전에 계정 접근·가격·크레딧 적용 여부를 확인해 정합니다. 관련도와 개발자 추천 순위는 검색 순위일 뿐이며 확률이나 인사 평가 점수가 아닙니다.
