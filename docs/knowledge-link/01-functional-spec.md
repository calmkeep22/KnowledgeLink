# 기능명세서와 유즈케이스

버전 0.2 · 2026-09-12 · 1인 개발 MVP 제안

## 1. 만들 서비스와 범위

개발자가 새 업무를 시작할 때 조직의 Jira 이슈와 GitHub PR에서 비슷하게 해결된 업무·관련 코드 변경·그 경험이 있는 개발자를 근거와 함께 찾는다. AI 결과는 탐색을 돕는 추천이며 사실 확정이 아니다. 모든 결과 항목은 원본 Jira·GitHub 링크로 확인할 수 있어야 한다.

첫 목표는 **단일 조직, Jira Cloud 프로젝트 1~2개, GitHub 저장소 1~2개(본인이 생성한 시나리오 데이터, 6장), 관리자·개발자 시연 계정**으로 동기화 → 색인 → 유사 업무 분석 → 질문의 전체 흐름을 끝까지 구현하는 것이다. 계정·scope 접근 목록·개발자 식별자 연결은 개발용 seed/운영 스크립트로 등록한다. 스크립트도 비밀번호 hash·조직·역할 검증을 적용한다. Jira·GitHub 인증 정보는 서버 환경 비밀값으로만 둔다.

후속 범위: Slack·Notion·Confluence 연동, webhook 실시간 수집, 원본 권한 자동 동기화, 계정·권한·식별자 관리 화면, 조직 지식 그래프 시각화, 코드 diff 본문 분석, Redis·Prometheus 등 인프라 확장(측정 근거가 생긴 뒤 결정).

## 2. 역할과 접근

| 역할 | 가능한 작업 |
| --- | --- |
| MEMBER | grant가 있는 scope 안에서 유사 업무 분석, 자연어 질문, 과거 업무·PR 상세와 해결 과정 요약 조회, 결과 피드백 |
| ADMIN | 같은 조직 모든 scope에 대한 MEMBER 기능, 동기화 실행·상태 확인, AI 추정 연결 확정·거절. 연결·scope·grant·식별자 등록은 운영 스크립트 |

scope는 Jira 프로젝트 1개 또는 GitHub 저장소 1개이며 접근 단위다. MEMBER는 grant가 있는 scope의 자료만 검색·열람·인용받는다. ADMIN도 다른 조직 자료에는 접근하지 못한다. grant는 해당 사용자의 원본 Jira·GitHub 권한보다 넓게 주지 않는 것을 운영 규칙으로 하며, 원본 권한과의 자동 대조는 후속 범위다.

이슈와 PR이 서로 다른 scope에 있으면 연결은 양쪽을 모두 볼 수 있을 때만 보인다. 개발자는 요청자에게 보이는 근거가 있을 때만 추천하며 근거 건수도 보이는 자료로만 센다. 숨겨진 자료는 개수로도 드러내지 않는다. 개인별 프로필·전체 활동 목록·순위표는 만들지 않는다.

| F04 | 이슈↔PR 연결 | 명시 키 연결 자동 생성, AI 추정 연결은 SUGGESTED로 분리, ADMIN 확정·거절이 재동기화 후에도 유지 |

| F08 | 해결 과정 요약 | 과거 이슈와 명시·확정 연결 PR로 문제·원인·해결·기술 요약. 문장마다 근거, 원본 변경 시 재생성 |

| F10 | 사용량 제한·피드백 | 외부 유료 호출 전 월 건수·예산 예약 검사, 사용량 불명 비용 보류, 결과별 도움됨·관련 없음 피드백 저장 |

## 4. 유즈케이스

유사 업무 결과는 WORK_ITEM 또는 CODE_CHANGE다. 명시·확정 연결 PR은 이슈 카드에 묶고, 연결 없는 PR은 단독 카드로 표시한다. 추정 연결만 있는 PR도 단독 후보로 유지한다. 권한 밖 이슈의 존재·연결 여부는 단독 PR 화면에서도 드러내지 않는다.

생성 답변·요약·요청 해석·관련도 이유·공용 카드에는 생성에 사용한 전체 sourceIds와 원본 버전을 기록한다. 하나라도 접근 불가 또는 HIDDEN이면 해당 생성물 전체를 숨긴다. 목록은 허용된 항목만 남기고 재생성은 사용자가 요청할 때 현재 권한·예산을 검사해 실행한다. 인용만 지운 채 본문을 제공하지 않는다.

| ID / 사용자 | 전제 | 정상 흐름 | 예외와 종료 조건 |
| --- | --- | --- | --- |
| UC01 관리자 동기화 | 연결 비밀값·scope 등록 완료 | 동기화 실행 → 진행 상태 확인 → 색인 완료 → 건수 확인 | 인증 실패는 연결 ERROR로 멈춤. 요청 제한은 대기 후 같은 커서에서 재개. 재실행해도 자료는 1건 |
| UC02 개발자 유사 업무 분석 | 로그인·scope grant | 이슈 키 또는 업무 설명 입력 → 작업 대기 → 유사 업무·연결 PR·개발자·요약 확인 → 원본 열기 | 비허용 scope 이슈 키는 없는 키와 같은 404. 후보가 없으면 "비슷한 과거 업무를 찾지 못했습니다" |
| UC03 개발자 과거 업무 확인 | 결과 항목 접근 가능 | 상세 열기 → 연결 PR과 배지 확인 → 해결 과정 요약 요청 → 근거 원본 대조 | 근거 부족 문장은 확인 필요 표시. 원본 삭제·범위 이탈 자료는 숨김 |
| UC04 개발자 자연어 질문 | scope grant | 질문 입력 → 대기 → 답·인용·관련 개발자 확인 | 근거 부족은 확인 불가. 생성 입력 중 접근 불가 자료가 생기면 과거 답 전체를 숨기고 사용자 요청으로 재생성 |
| UC05 관리자 추정 연결 검토 | SUGGESTED 연결 존재 | 목록 → 근거 비교 → 확정 또는 거절 | 확정한 것만 "연결됨". 거절한 쌍은 다시 제안하지 않음. 동시 결정은 하나만 성공 |
| UC06 실패 복구 | 재시도 가능 실패, 시도 여유 | 자동 대기 또는 재시도 → 같은 job의 커서·미완료 단계부터 재개 | 인증·설정 오류는 자동 재시도 안 함. 과금 불명은 자동 재호출 금지 |

## 5. 초기 제한과 미결정 사항

아래 수치는 구현용 제안값이며 평가 세트로 조정한다.

| 항목 | 기본값 |
| --- | --- |
| 소스 범위 | Jira 프로젝트 2개·GitHub 저장소 2개 이하, scope당 최근 24개월·최대 3,000건 |
| 이슈 수집 | 제목·설명·유형·상태·해결 여부·라벨·컴포넌트·담당자·해결일·최근 댓글 20개 |
| PR 수집 | 제목·본문·브랜치·상태·병합일·작성자·리뷰어·커밋 메시지 100개·변경 파일 경로와 증감 300개 |
| 코드 본문 | diff 본문은 수집·AI 전송하지 않음. 파일 경로·통계와 GitHub 링크만 제공 |
| 동기화 | 수동 실행 + 30분 간격 증분, 커서 겹침 10분, 정합성 점검 하루 1회 |
| 동시 작업 | 서버 전체 SYNC(동기화·정합성 점검) 1개, INDEX(색인·임베딩) 1개, AI(분석·질문·요약·연결 추정 합산) 1개. INDEX와 AI는 동시 실행 가능 |
| 입력 | 업무 설명·질문 1000자, 청크 800토큰 이하 |
| 결과 | 유사 업무 5건, 관련 개발자 3명, 항목별 근거 5개 이하 |
| AI 입력·출력 | 호출당 입력 16000토큰·출력 2000토큰 이하 |
| 재시도 | 최초 포함 3회. 인증·설정·입력 오류는 재시도 안 함 |
| 유료 기본 설정 | 비활성, 월 예산·건수 0. fake AI(결정적 임베딩·고정 응답)로 개발 |
| AI 월 한도 | 제안 5달러(설정값). 가격표 확인 후 조정하며 초과 시 유료 요청 차단 |

외부 AI 전송 필드와 AI 공급자는 유료 평가 전에 정한다. 평가 질의 30개로 관련도 구간 경계와 운영값을 정한다. 품질·지연 합격선은 테스트 체크리스트에서 결정한다.

## 6. 데모 데이터와 비용 원칙

### 데모 데이터 (결정)

본인이 만든 Jira Cloud 무료 사이트와 본인 GitHub 저장소에 시나리오 데이터를 생성하고, 서비스는 이를 실제 API로 수집한다. 생성은 별도 시나리오 생성 스크립트로 하며 재실행해도 이슈·PR을 중복 생성하지 않는다. 시나리오 문서는 사람이 검수한다.

| 항목 | 제안 |
| --- | --- |
| 규모 | Jira 프로젝트 2개(예: 결제 PAY, 주문 ORD)·이슈 합계 120~200건, 저장소 2개·PR 합계 100~150건 |
| 인물 | 가상 개발자 5~6명. 커밋 작성자 이름·이메일(`@example.com`)로 표현 |
| 연결 비율 | PR의 약 70%는 이슈 키 포함, 20%는 키 없음, 나머지는 오탐 문자열·미등록 키 포함 |
| 검증용 자료 | 키워드는 다르지만 같은 문제인 쌍, 단어는 같지만 다른 문제인 함정, 이동 이슈, 삭제 이슈, 프롬프트 주입 이슈, 가짜 비밀값 패턴 |

시나리오 데이터에는 두 가지 제약이 있다.

- **인물 표현:** GitHub 약관상 개인 무료 계정을 여러 개 만들 수 없으므로 PR 작성자는 모두 본인 계정이다. 인물은 커밋 작성자 정보로 표현하고, 데이터 생성 계정은 recommendable=false로 추천에서 뺀다. Jira 담당자는 실제 사용자만 지정할 수 있어 기본은 비워 둔다. 이슈의 기여자는 명시·확정 연결 PR의 커밋 작성자로 계산한다. Jira 무료 플랜에 본인 소유 이메일로 사용자를 추가할 수 있으면 담당자도 인물별로 지정한다.
- **날짜:** 이슈 생성·해결 시각과 PR 병합 시각은 API로 과거 날짜를 넣을 수 없어 모두 최근 날짜다. 커밋 작성 시각만 과거로 기록할 수 있다. 최근성 가중치는 화면 시연 대신 단위 테스트 fixture로 검증한다.

### AWS 최소 비용 운영

| 항목 | 방침 |
| --- | --- |
| 개발 | 로컬 docker compose(PostgreSQL+pgvector)와 fake AI. AWS 비용 없음 |
| 데모 서버 | 서버 1대에서 Nginx·Spring Boot를 docker compose로 실행하고, DB는 Amazon RDS for PostgreSQL 17(Single-AZ)을 쓴다([ADR 0004](../adr/0004-rds-postgresql-for-production.md)). React 빌드 파일은 Nginx로 제공. 앱 서버는 RDS와 같은 VPC에 두며(Lightsail은 VPC peering이 필요해 EC2 우선) 메모리 2GB 이상 최소 사양을 견적 비교 후 선택 |
| 쓰지 않는 것 | RDS Multi-AZ, 로드밸런서, NAT Gateway, 관리형 벡터 DB·검색 서비스, 컨테이너 오케스트레이션 |
| 운영 시간 | 상시 운영 대신 데모·심사 기간에만 앱 서버와 RDS를 켠다. 중지 중 과금 방식은 상품마다 달라 선택 시 확인. RDS는 중지 7일 후 자동으로 다시 시작되므로 긴 휴지 기간에는 스냅샷 후 삭제를 검토 |
| 백업 | RDS 자동 백업(보존 7일)과 시점 복구 |
| HTTPS | 무료 인증서(Let's Encrypt). 도메인은 선택 |
| 비밀값 | 서버 환경 파일 권한 제한, 저장소 커밋 금지 |
| 비용 확인 | AWS 예산 알림 설정. 알림은 차단 장치가 아니므로 앱의 AI 월 한도로 유료 호출을 막는다 |
| AI 공급자 | OpenAI API와 Amazon Bedrock을 adapter로 교체할 수 있게 둔다. AWS 크레딧을 Bedrock 요금에 쓸 수 있는지 확인 후 결정 |

실제 월 비용은 서버·RDS 사양, 리전, 운영 시간, 공인 IP, 저장·백업 용량, AI 사용량에 따라 달라지며 이 문서는 견적이 아니다. 가격과 크레딧 조건은 가입·배포 시 공식 안내로 확인한다.
