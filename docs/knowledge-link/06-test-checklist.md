버전 0.2 · 아래 항목은 구현 수용 기준이다. 체크한 항목만 실제로 실행해 통과했으며, 결과는 [테스트 결과 기록](../testing/test-report.md)에 남긴다.

## 1. 준비

로컬 PostgreSQL+pgvector(Testcontainers), fake AI(결정적 임베딩·고정 응답), ADMIN·전체 scope MEMBER·일부 scope MEMBER·다른 조직 사용자를 준비한다. Jira·GitHub는 녹화한 응답으로 계약 테스트를 하고, 실제 연동은 시나리오 데이터를 생성한 본인 Jira Cloud 사이트와 GitHub 저장소에서 확인한다. 시나리오 생성 스크립트는 재실행해도 이슈·PR을 중복 생성하지 않는다. DB 경합 검사는 실제 PostgreSQL의 서로 다른 connection에서 실행한다.

fixture: 명시 키가 있는 PR, 키 없는 병합 PR, 미등록 키·`UTF-8` 문자열이 든 PR, 다른 프로젝트로 이동한 이슈, 삭제된 이슈, 프롬프트 주입 문장이 든 이슈, 가짜 비밀값 패턴이 든 이슈·커밋, 미연결 식별자, 커밋 작성자만 다른 PR, 과거 커밋 작성 시각을 가진 최근성 fixture.

## 7. 검색 품질 평가

### 추가 계약 검증

- [ ] T32 ANALYSIS/QUESTION/CARD/LINK_SUGGEST를 서로 다른 DB connection으로 동시에 선점해도 AI 슬롯에서 하나만 RUNNING. scope가 다른 SYNC/RECONCILE도 서버 전체 하나만 실행. INDEX와 AI 동시 실행은 허용. 슬롯 대기는 시도 횟수 미소비, 종료·재시작 복구 시 슬롯 누수 없음. (F02/F03/F06/F09)
- [ ] T33 단독 PR은 CODE_CHANGE/source.repository/source.number로 반환하고 S05로 이동. WORK_ITEM은 source.issueKey와 S04 이동. 명시·확정 연결 PR은 이슈 카드에 묶고 단독 중복 없음, 추정 연결만 있으면 단독 유지, 비허용 연결 이슈 존재 미노출. 두 유형의 피드백·없는 ID·권한 검사 확인. (F06/F10)
- [ ] T34 REGENERATION_REQUIRED 조회는 유료 호출 0회, null 본문·빈 인용·고정 안내만 반환. 명시 재생성은 현재 권한·예산 검사 후 새 분석/질문 ID 사용. 공용 카드는 접근 범위별 캐시 분리, 거절 시 기존 결과 불변. (F08/F09/F10)

평가 질의 30개를 제안한다. 과거에 같은 문제가 명확히 있는 질의 10개, 키워드는 다르지만 같은 문제인 질의 10개, 과거 사례가 없는 질의 10개다.

시나리오 데이터를 만든 사람이 정답도 알고 있으므로 편향을 줄이는 규칙을 둔다. 질의 문장은 이슈 제목을 그대로 쓰지 않고 다른 표현으로 쓴다. 단어는 같지만 다른 문제인 함정 이슈를 포함한다. 관련 과거 이슈·PR·관련 경험자 정답표는 시스템을 한 번이라도 실행하기 전에 확정하고, 이후 수정하면 사유를 기록한다.

키워드만(pg_trgm) / 벡터만 / 혼합 / 혼합+재정렬을 같은 질의로 비교한다. 제안 합격선은 다음과 같다.

- 사례가 있는 질의 20개의 Recall@5 0.8 이상
- 키워드가 다른 질의 10개에서 혼합+재정렬의 Recall@5가 키워드만보다 높음
- 사례가 없는 질의 10개에서 HIGH 표시 0건
- 관련 경험자 상위 3명 안에 정답자 포함 비율 0.7 이상
- 화면에 표시된 추정 연결의 정밀도 0.9 이상
- 권한 위반·없는 근거 인용 0건

관련도 구간 경계와 추정 연결 기준값은 이 평가로 정한다. 완료 판정 전에 합격선을 확정하고 임의로 PASS 처리하지 않는다.

질의별 지연·외부 호출 수·비용과 scope별 동기화·색인 시간·비용을 기록한다. 초기 제안은 분석 p95 20초 이내다. 표본 30개와 직접 만든 데이터로 실제 조직에서의 정확도나 월 비용을 보장하지 않는다. 모델·프롬프트·청크·가중치 변경 시 같은 평가를 다시 한다.
