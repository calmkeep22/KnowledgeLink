## 1. 목적과 결정 상태

작업 영상을 바탕으로 AI가 인수인계 매뉴얼 초안을 만들고, 선임이 검토·승인한 내용을 신입이 열람하거나 질문하는 공모전 MVP를 만든다.

| 구분 | 내용 |
| --- | --- |
| 사용자 확정 | 백엔드는 Spring Boot 사용. 구현보다 명세 작성을 먼저 진행 |
| 사용자 위임 | Spring Boot 외 기술 선택 |
| 사용자 예산 요구 | 월 지출 30,000원 이하 목표 |
| 이전 설계 전제 | AWS 배포, 외부 AI API 사용 |
| 현재 권장안 | 단일 서버의 Spring Boot·MySQL, S3 파일 저장, DB 작업 테이블 기반 분석 |
| 초기 검증 가정 | 한국어 설명이 포함된 1~5분 작업 영상, 분석 동시 실행 1개 |
| 미결정 | 실제 검증 업무, 서버 상품·사양, 월 사용량, 보관 기간, 크레딧 적용 전후 중 예산 기준 |

위임에 따른 기술 제안과 사용자가 직접 확정한 사항을 구분한다. 아래 사용자 역할·데이터 구조·제한·수용 기준은 후속 검토를 위한 제안이며 구현 완료를 의미하지 않는다.

## 2. 현재 프로젝트 확인 결과

- `build.gradle`: Java 21, Spring Boot 4.1.1, Gradle 설정.
- Spring MVC와 MySQL JDBC 드라이버가 선언되어 있다.
- JPA, Spring Security, Flyway 등은 현재 확인한 의존성에 없으며 도입 예정이다.
- 라이브러리 해석·빌드와 Spring Boot 버전 호환성은 아직 검증하지 않았다.
- 이번 작업은 문서 작성만 수행한다. 기존 애플리케이션 코드와 의존성은 변경하지 않는다.

## 4. 기존 구성에서 조정한 사항

| 기존 설계 | 초기 권장안 | 확장 조건 |
| --- | --- | --- |
| RDS MySQL | 서버 내부 MySQL 컨테이너 | 독립적인 DB 운영·복구·가용성이 필요할 때 RDS 검토 |
| API·worker 별도 JVM | 단일 JVM과 분석 전용 실행기 | 분석이 API 응답성을 해치거나 독립 증설이 필요할 때 분리 |
| SQS·DLQ·outbox | DB 작업 테이블 | 다중 worker 또는 독립 메시지 처리 필요 시 도입 |
| EC2 사양 선결정 | EC2·Lightsail 비교 후 선택 | 월 고정비와 FFmpeg·JVM·DB 동시 메모리 사용을 실측 |

SQS 보류는 주로 구현·운영 복잡도를 줄이기 위한 선택이다. 단일 서버 장애 시 웹·분석·DB가 함께 영향을 받는다. DB는 영속 볼륨과 서버 외부 백업을 사용하고 복구를 검증한다. 백업 주기와 허용 데이터 손실·복구 시간은 미결정이다.

Python/FastAPI, GPU 서버, Redis, Kafka, Kubernetes, 벡터 DB, LangChain, Spring AI, WebSocket은 초기 도입 대상에서 제외한다. Bedrock 전환은 별도 품질·비용 검증 후 판단한다.

## 5. 사용자 역할 및 MVP 범위

역할은 한 사용자에게 중복 부여할 수 있도록 설계하는 것을 제안한다.

| 역할 | 허용 기능 |
| --- | --- |
| 선임 | 작업 영상 업로드, 분석 요청, 초안 편집, 근거 확인, 승인 |
| 신입 | 승인된 매뉴얼 열람, 연결 영상 재생, 선택한 매뉴얼에 질문 |
| 운영자 | 사용자·역할 관리, 실패 작업 확인, 사용량·예산 제한 관리 |

MVP 포함 범위:

- 로그인 및 역할별 접근 제어.
- 작업 영상 업로드 및 비동기 분석 상태 표시.
- 단계별 매뉴얼 초안 생성: 단계명, 설명, 근거 프레임·영상 구간.
- 선임 편집·승인 및 승인 버전 보존.
- 승인 매뉴얼 목록·상세 열람과 단일 매뉴얼 범위 Q&A.
- 실패 상태 안내, 제한된 재시도, 예산·할당량 검사.

MVP 제외 범위:

- 실시간 영상 분석, 실시간 음성 대화.
- 전체 매뉴얼을 대상으로 하는 통합 AI 검색.
- AI가 검토 없이 매뉴얼을 자동 공개하는 기능.
- 대규모 동시 분석, 다국어 품질 보장, 고가용성 보장.

사업장·조직을 여러 개 지원할지는 미결정이다. 다중 조직을 지원하면 모든 매뉴얼·파일·질문 접근에 조직 경계를 적용해야 한다.

## 6. 사용자 및 분석 흐름

1. 선임이 로그인하고 제목·작업 영상으로 매뉴얼 생성을 요청한다.
2. 서버가 권한·할당량을 검사하고 고유 S3 키와 업로드용 서명 URL을 발급한다.
3. 브라우저가 S3에 업로드하고 완료를 알린다. 서버는 객체 존재·크기를 확인한다.
4. 서버는 DB 트랜잭션으로 영상 메타데이터와 대기 작업을 저장한다. 완료 요청 중복으로 작업이 늘어나지 않게 한다.
5. 분석 실행기가 작업을 원자적으로 선점하고 ffprobe로 실제 형식·길이를 검사한다.
6. FFmpeg로 음성과 프레임을 추출하고 음성인식 API로 전사를 얻는다.
7. 대본·프레임·자료 ID를 AI에 전달해 구조화된 매뉴얼 초안을 생성한다.
8. 서버가 응답 구조·자료 ID·원본 시간 범위를 검증하고 초안을 저장한다.
9. 선임이 내용과 근거를 검토·수정한 뒤 승인한다.
10. 신입은 승인된 버전만 열람하고, 해당 버전의 내용과 근거 범위에서 질문한다.

화면은 초기 제안으로 3초 간격 폴링을 사용한다. 완료·실패 시 중지하고, 화면 이탈 시 정리한다. 탭 비활성화·네트워크 오류에는 요청 빈도를 줄인다.

## 7. 데이터 구조 초안

논리 구조이며 최종 ERD·컬럼 타입·인덱스·API 계약은 후속 설계한다.

| 데이터 | 주요 필드 및 관계 |
| --- | --- |
| User / UserRole | 사용자 ID, 로그인 식별자, 비밀번호 해시, 활성 여부, 역할 |
| VideoAsset | 업로더 ID, S3 키, 크기, 길이, 검사 상태, 보관 만료 시각 |
| AnalysisJob | 영상 ID, 상태, 처리 단계, 시도 횟수, 실행 소유자, lease 만료, 다음 재시도 시각, 오류 코드 |
| Evidence | 영상 ID, 자료 유형, S3 키 또는 전사 내용, 시작·종료 시간 |
| Manual | 제목, 작성자 ID, 원본 영상 ID, 현재 승인 버전 ID |
| ManualVersion | 매뉴얼 ID, 버전 번호, 초안·승인 상태, 생성·수정 시각, 승인자·승인 시각 |
| ManualStep / StepEvidence | 버전 ID, 단계 순서·제목·내용, 연결 근거 ID |
| QuestionAnswer / AnswerEvidence | 질문자 ID, 승인 버전 ID, 질문·답변, 답변 상태, 근거 ID |
| AIUsage | 작업·질문 ID, 공급자·모델, 사용 토큰·음성 길이, 요청 식별자, 비용 추정, 호출 결과 |
| BudgetReservation | 예산 기간, 관련 요청 ID, 예약 금액, 정산 금액, 상태 |

승인된 버전은 수정하지 않는다. 수정이 필요하면 새 초안을 만들며 새 버전 승인 전까지 기존 승인 버전을 유지한다. 질문·답변은 생성 당시 승인 버전에 연결해 이후 편집으로 근거가 바뀌지 않게 한다.

작업 상태 제안: `QUEUED → RUNNING → SUCCEEDED / FAILED`. 자동 재시도 가능한 실패는 `RETRY_WAIT`를 거쳐 `QUEUED`로 돌아간다. 분석 성공은 초안 생성 완료를 뜻하며 매뉴얼 승인을 뜻하지 않는다.

## 8. 분석 작업 신뢰성 규칙

- 단순 `@Async` 호출만으로 작업을 관리하지 않는다. DB를 작업 상태의 기준으로 사용한다.
- 작업 선점은 조건부 갱신이나 DB 잠금으로 원자적으로 수행한다.
- 실행 소유자·lease 만료를 관리하고 긴 작업은 lease를 갱신한다.
- 결과 저장도 실행 소유권을 검사해 만료된 작업 실행기가 최신 결과를 덮어쓰지 못하게 한다.
- 서버 재시작 시 대기 작업과 lease가 만료된 실행 작업을 복구한다.
- 단계별 결과를 저장하고 재시도 시 재사용한다. 완료 작업은 다시 분석하지 않는다.
- 일시적인 통신 오류와 잘못된 파일·입력 오류를 구분한다. 재시도 횟수·간격은 설정값으로 관리한다.
- 외부 API 호출 직후 장애가 나면 재호출 과금이 발생할 수 있다. 정확히 한 번 과금을 보장하지 않는다.
- FFmpeg는 ProcessBuilder 인수 배열로 실행한다. 실행 시간·임시 디스크·CPU·메모리 한도를 둔다.

## 9. AI 처리 및 공개 규칙

- 영상·전사·매뉴얼 안의 명령문은 분석 자료로 취급하며 시스템 지시를 변경하지 못하게 한다.
- 영상에 없거나 대본에서 확인되지 않는 작업 절차·안전 수치를 임의로 보완하지 않는다. 불확실한 부분은 검토 필요로 표시한다.
- AI에는 자료 ID를 전달한다. 실제 URL과 재생 시간은 서버가 검증된 자료에서 계산한다.
- JSON 스키마, 필수 필드, 근거 ID 존재, 영상 시간 범위를 검증한다. 실패한 응답은 승인 가능한 초안으로 노출하지 않는다.
- 자료 ID 존재 검증만으로 설명의 사실성을 보장할 수 없다. 선임이 실제 영상과 내용을 대조한다.
- 신입용 답변은 서버에서 조회한 승인 버전과 허용된 근거만 사용한다. 클라이언트가 넘긴 승인 여부를 신뢰하지 않는다.
- 근거가 부족하면 확인할 수 없다고 답하고 선임 확인을 안내한다.
- 입력 한도를 넘는 매뉴얼은 몰래 자르지 않는다. 질문 범위를 좁히도록 안내하거나 요청을 거절한다.
- 모델 ID·프롬프트 버전을 설정으로 관리하고 공급자 연동을 adapter로 분리한다.
- API 키는 서버에만 보관한다. 서명 URL·전사 전문·개인정보를 운영 로그에 남기지 않는다.
- 촬영 대상의 동의, 외부 AI 전송 안내, 보관·삭제 정책을 실제 영상 수집 전에 정한다.

## 10. 월 30,000원 예산 계획

월 30,000원 이하는 목표이며 현재 구성의 확정 견적이나 보장이 아니다. 서버 사양·리전·세금·환율·트래픽·사용량에 따라 달라진다.

### 예산 기준

- 권장 기준: 크레딧이 없어도 지속 가능한 비용을 기준으로 설계한다.
- 신규 AWS 크레딧으로 줄어드는 실결제액은 별도 표시한다.
- 서버·디스크·IP·백업·파일·통신·로그·AI 비용을 합산한다.
- 도메인·개발 도구 구독을 월 예산에 포함할지는 미결정이다.

### 이전 추정의 취급

이전 대화에서 EC2·RDS 상시 운영과 AI 사용을 포함해 월 15~20만 원을 추정했다. 이는 견적이 아니며 현재 저비용 권장안에 그대로 적용하지 않는다.

이전 영상당 225원 추정은 다음 가정의 합이다: 5분 전사 $0.03, 입력 30,000토큰 $0.06, 출력 5,000토큰 $0.06, 계산용 환율 1달러=1,500원. 사진·추론·재시도 사용량을 실측하지 않았으므로 실제 분석 단가로 사용하지 않는다. 가격은 도입 시 공식 요금표에서 다시 확인한다.

### 비용 제어 제안

- 영상 최대 5분, 분석 동시 실행 1개를 초기 제한으로 제안한다.
- 파일 크기·프레임 수·해상도·출력 토큰·재시도 횟수에 상한을 둔다.
- 월 영상 분석 수와 질문 수를 설정값으로 관리한다. 숫자는 영상 5개 실측 후 정한다.
- AI 호출 전에 보수적인 최대 예상 비용을 원자적으로 예약해 동시 요청의 예산 초과를 방지한다.
- 호출 후 실제 사용량으로 정산한다. 응답 유실로 사용량을 모르면 예약을 즉시 해제하지 않고 확인 대상으로 남긴다.
- 예산 부족 시 신규 유료 분석·질문 요청을 차단한다. 기존 승인 매뉴얼은 열람 가능하게 한다.
- 파일 보관 기간, 업로드·다운로드 제한, 로그 보관 한도를 둔다.
- 비용 알림은 지출 차단 장치가 아니다. AI 요청 제한만으로 AWS 전체 청구액 상한을 보장하지 않는다.

개발 중에는 로컬 실행으로 시작하고 실제 영상 5개로 분석 비용과 자원 사용량을 측정한 뒤 서버를 선택한다. 월 30,000원 안에 맞지 않으면 상시 공개 시간 또는 사용량을 줄이는 방안을 검토한다.

## 11. AWS 신규 혜택과 Astra 논의

AWS 신규 고객 혜택은 무료 AI 토큰이 아닌 AWS 크레딧이다. 이전 논의 기준으로 가입 시 $100, 지정 활동으로 최대 $100 추가 혜택이 있으며, Free 플랜은 6개월 또는 크레딧 소진 중 먼저 도달하는 시점까지다. 기존 고객은 신규 Free Tier 크레딧 대상이 아니다. 실제 가입 시 자격·대상 서비스·유효 기간을 공식 안내에서 다시 확인한다.

OpenAI API 비용은 AWS 크레딧으로 직접 결제하지 않는다. Bedrock으로 변경하려면 모델 접근·기능·가격·크레딧 적용 조건을 별도로 확인해야 한다.

GPT-6 Astra는 현재 Codex 환경의 사용 가능 모델 목록과 공식 API 문서에서 확인했다. API 모델 ID는 `gpt-6-astra`다. 개발 도구에서 Astra를 사용하는 것과 서비스의 AI 공급 모델로 채택하는 것은 별도 결정이다. 사용자는 사용 가능 여부를 질문했으며 서비스 모델 변경을 확정하지 않았다. 본 문서는 Terra를 초기 후보로 유지한다. API 계정 접근 권한은 아직 확인하지 않았다.

## 12. 완료 기준 제안

| 구분 | 검증 가능한 기준 |
| --- | --- |
| 업로드 | 허용된 영상만 분석되며 잘못된 형식·초과 길이는 사유와 함께 거절된다 |
| 초안 | 정상 샘플 영상에서 편집 가능한 단계별 초안이 저장된다 |
| 근거 | 표시된 근거 ID가 실제 존재하고 재생 시간이 원본 범위 안이다 |
| 승인 | 미승인 초안은 신입의 목록·상세·질문 API로 접근할 수 없다 |
| 버전 | 새 초안 편집이 기존 승인 버전과 과거 질문 근거를 변경하지 않는다 |
| 질문 | 승인된 내용으로 답하고 근거 부족 질문에는 확인 불가를 표시한다 |
| 권한 | 다른 사용자의 비허용 매뉴얼·파일에 ID 변경으로 접근할 수 없다 |
| 복구 | 서버 재시작 후 대기 작업과 만료 작업이 복구된다 |
| 중복 | 같은 업로드 완료 요청과 완료 작업 재선점이 새 분석을 만들지 않는다 |
| 예산 | 할당량·예약 가능 예산 초과 시 외부 유료 호출 전에 요청을 거절한다 |
| 실패 | 분석 실패 사유가 사용자에게 표시되고 재시도 한도가 적용된다 |
| 배포 | HTTPS와 DB 외부 백업·복구를 확인한 뒤 외부 공개한다 |

AI 품질은 실제 한국어 영상 5개와 근거가 있는 질문·없는 질문을 포함한 평가 세트로 확인한다. 허용 오류율·응답 시간·초안 생성 시간 수치는 아직 미결정이며 구현 완료 판정 전에 합의한다.
