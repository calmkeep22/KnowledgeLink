# ADR 0002. JWT 대신 서버 세션을 쓰고 요청마다 계정 상태를 다시 확인한다

- 상태: 채택
- 날짜: 2026-09-12

## 맥락

계정·권한은 운영 스크립트로 바뀐다. 비활성화·비밀번호 변경·역할 변경은 로그인 중인 사용자에게도 바로 반영돼야 한다(명세 F01, T01). 프론트엔드는 같은 도메인의 SPA이며 서버는 1대다.

## 결정

- Spring Session JDBC로 세션을 PostgreSQL에 저장하고, 쿠키는 HttpOnly·SameSite=Lax·운영에서 `__Host-` 접두사와 Secure를 쓴다.
- CSRF 토큰은 세션에 저장하고 SPA가 `GET /auth/csrf`로 받아 헤더로 보낸다.
- `AccountRevalidationFilter`가 요청마다 계정을 PK로 조회한다.
  - 비활성·삭제·자격 버전(`credential_version`) 불일치: 세션을 끊는다.
  - 역할·초기 비밀번호 변경 여부 변경: 세션의 인증 정보를 갱신한다.

## 이유

- JWT는 만료 전 폐기를 하려면 차단 목록이 필요하고, 결국 서버 상태를 다시 두게 된다.
- 비밀번호 변경 시 "다른 세션 모두 종료"를 세션 목록 조회 없이 자격 버전 비교 하나로 처리할 수 있다.
- 추가 비용은 인증된 요청당 PK 조회 1회다.

## 대안

| 대안 | 채택하지 않은 이유 |
| --- | --- |
| JWT(Access+Refresh) | 즉시 폐기에 별도 저장소가 필요하고 XSS 시 토큰 탈취 범위가 넓다 |
| 세션만 쓰고 재검증 없음 | 비활성화·역할 변경이 세션 만료(8시간)까지 반영되지 않는다 |

## 결과

- 서버를 2대 이상으로 늘리면 세션 저장소를 Redis로 옮기는 것을 검토한다. 요청당 계정 조회가 병목으로 측정되면 짧은 TTL 캐시를 검토한다.
- 로그인 시도 제한(무차별 대입 방어)은 아직 없다. 공개 배포 전 추가한다.
